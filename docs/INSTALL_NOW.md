### 🚨 الإصلاح 7 (الأخطر) — كيف كان يمكن الاستيلاء على التطبيق

اجتمعت ثلاثة أمور:

1. **تأكيد البريد مُطفأ** — إلزامي، لأن `js/app.js:476` ينفّذ `signUp` ثم `signIn`
   فوراً، فلو كان التأكيد مفعّلاً لما استطاع أي مستخدم جديد الدخول.
2. **الـ Trigger يمنح `is_admin` تلقائياً** لأي بريد في القائمة.
3. **الحسابات غير مسجّلة** → الإيميل غير محجوز.

**الهجوم بلا موقع حتى:** يكفي المفتاح العام + معرّف المشروع (وكلاهما منشور
في هذا المستودع العام) للنداء على:

```bash
curl -X POST "https://<ref>.supabase.co/auth/v1/signup" \
  -H "apikey: <sb_publishable_...>" -H "Content-Type: application/json" \
  -d '{"email":"admin@sharaf.com","password":"..."}'
```

فيدخل المهاجم **مشرفاً عاماً** يقرأ كل المحادثات — بلا بريد ولا كلمة مرور
لأحد.

**الإصلاح:** أُزيل منح الصلاحيات من `handle_new_user` نهائياً. البريد الآن
مجرد **مفتاح تعريفي للترقية اليدوية**، لا صلاحية تُمنح ذاتياً.

## 👤 كيف يُصبح الشخص مشرفاً (بعد الإصلاح)

```
1) يسجّل حسابه بنفسه من شاشة «إنشاء حساب» في التطبيق
2) شغّل:  sql/promote_admins.sql   (من SQL Editor — مرة واحدة)
3) تحقق: التقرير في نهاية الملف يُظهر is_super_admin = true لصفّه
```

الملف **يُرقّي ولا يُخفّض أبداً**، فتشغيله المتكرر آمن، وتشغيله بقائمة فارغة
لا يفعل شيئاً.

> بديل أسرع لمشرف واحد بدون ملف:
> ```sql
> update public.profiles set is_admin = true, is_super_admin = true
>  where lower(email) = 'admin@sharaf.com';
> ```

## 🔴 المطلوب منك الآن

**سجّل حسابات المشرفين** — كل واحد من هؤلاء يسجّل بنفس الإيميل المكتوب في
القائمة (لا تجربة بـ إيميل آخر، وإلا لم يُرقَّ):

```
admin@sharaf.com        ← المشرف العام  (الأهم: سجّله أولاً)
111@admin.com  222@admin.com  333@admin.com  444@admin.com  555@admin.com
```

⚠️ **تنبيه مهم:** هذان الأمران يجب أن يتحققا:
- البريد **حقيقي وتملك صندوقه** → بدونه لا يمكن استعادة كلمة المرور.
- أو **أزِله من القائمة** إن كان مجرد اسم مؤقت لم يُخصَّص لأحد.

أخبرني بعد التسجيل وأُشغّل الترقية فوراً (أو شغّل `sql/promote_admins.sql`
بنفسك في SQL Editor).
