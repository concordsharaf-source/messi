# اختبارات المخطط والسياسات (sql/tests)

هذه الأدوات تُشغّل PostgreSQL محلياً وتحاكي بيئة Supabase، ثم تتحقق من أن
`sql/schema.sql` و`sql/fcm_and_rls.sql` **يعملان** وأن سياسات RLS **تحمي فعلاً**.

> 💡 السبب: أخطاء SQL لا تظهر إلا عند التنفيذ الفعلي. تشغيلها محلياً يكشفها
> قبل لمس مشروعك الحقيقي — حيث لا يوجد نسخ احتياطي في الخطة المجانية.

## التشغيل

```bash
# 1) يشغّل PostgreSQL ويثبّت المحاكاة (auth.users / storage / الأدوار / النشر)
bash sql/tests/local_pg_up.sh

# 2) ينفّذ الملفين ويطبع أي خطأ برقم السطر + الحالة النهائية
bash sql/tests/run_schema_test.sh

# 3) 43 اختباراً سلوكياً على RLS بمحاكاة 4 مستخدمين (عاديّ/مشرف/غريب/مشرف عام)
bash sql/tests/rls_tests.sh
```

النتيجة المتوقعة: `schema.sql=0 fcm_and_rls.sql=0` ثم `43 ناجح / 0 فاشل`.

## الملفات

| الملف | الوظيفة |
|---|---|
| `00_supabase_stub.sql` | يحاكي ما يديره Supabase تلقائياً: `auth.users`, `auth.uid()`, `storage.buckets`, `storage.objects`, `storage.foldername()`, أدوار `anon/authenticated/service_role`, منشور `supabase_realtime`. **لا يُشغَّل على Supabase أبداً.** |
| `local_pg_up.sh` | يثبّت PostgreSQL 17 (إن لم يكن موجوداً)، ينشئ عنقوداً في `/tmp/pgdata`، يصفّر القاعدة، ويثبّت المحاكاة. |
| `run_schema_test.sh` | ينفّذ الملفين بـ `ON_ERROR_STOP=1` ويطبع الأخطاء، ثم يعرض الجداول والسياسات والـ buckets والـ Trigger وعدد جداول البث. |
| `rls_tests.sh` | اختبارات سلوكية: يرتدي دور `authenticated` مع claims مستخدم وهمي ويسأل: هل يرى؟ هل يستطيع التعديل؟ هل يُمنع؟ |

## ما الذي تُثبته الاختبارات فعلاً

- ✅ **الـ Trigger** `on_auth_user_created` ينشئ صف `profiles` عند كل تسجيل،
  ويأخذ `display_name` من `raw_user_meta_data`.
- ✅ **حماية تصعيد الصلاحيات**: المستخدم لا يستطيع ترقية نفسه إلى `is_admin`
  أو `is_super_admin`، ولا تعديل ملف غيره.
- ✅ **عزل المحادثات**: الغريب (غير المشارك) لا يرى المحادثة، ولا الرسائل،
  ولا حالة الكتابة — ولا يستطيع انتحال `sender_id` لغيره.
- ✅ **عزل التخزين**: كل مستخدم يرفع داخل مجلد `auth.uid()` فقط، ولا يرفع إلى
  bucket غير مسموح.
- ✅ **رموز الإشعارات**: `claim_fcm_token` تُرفض لمن يحاول ربط رمز بحساب غيره.
- ✅ **الزوار (`anon`)** لا يرون أي صف في `profiles` ولا في `messages`.
- ✅ **الحذف**: المستخدم العادي لا يحذف رسالة (`0` صفوف)، والمشرف يحذف.
- ✅ **المشرف العام** يرى محادثات الجميع عبر `current_is_super_admin()`.

## ملاحظات

- عنقود البيانات في `/tmp` — لا يُحفظ بين الجلسات، وأعد التشغيل من `local_pg_up.sh`.
- إن ظهرت أخطاء في اختبارات RLS فغالباً المخطط تغيّر: اقرأ السطر
  `المتوقع: «…» — الحاصل: «…»` لمعرفة الفرق.
- لتغيير هوية المستخدمين الوهميين: متغيّرات البيئة `U`, `A`, `O`, `S`.
